Routa is open source under the MIT License. The repository is a pnpm workspace holding
three published packages, two example applications, this documentation site, and a design
lab. Framework checks, tests, and package builds use the locally pinned Vite Plus toolchain.

## Before You Start

- Node.js 24.11 or later on the Node 24 line, or Node.js 26 or later. `.nvmrc` selects Node 24.
- pnpm 11.9.0, pinned in the root manifest. The repository uses workspace protocol links.
- A read of the v0 requirements and current public scope. Maintainers coordinate planned
  V1 work through the project-local tracker described in `docs/agents/issue-tracker.md`.

## Steps

<Steps>
1. Install dependencies from the repository root.

	```sh
	pnpm install --frozen-lockfile
	```

2. Run the full check suite before making changes, so you know the baseline is green.

	```sh
	pnpm check
	pnpm typecheck
	pnpm build
	pnpm test
	```

	`pnpm check` combines Oxfmt, type-aware Oxlint, compiler diagnostics, and the remaining
	Biome checks. `pnpm typecheck` also runs explicit TypeScript source and test programs
	and Astro checks. `pnpm build` builds the packages, examples, and sites. `pnpm test`
	runs all framework tests with Vite Plus's bundled Vitest.

	Only package compilation is cached. Tests and type checks execute on every run.
	A global Vite Plus installation is optional. Generated applications retain their
	existing TypeScript, Biome, and Vitest tooling.

3. Make the change in the package that owns the behavior.

	| Path | Owns |
	| --- | --- |
	| `packages/core` | Route, middleware, config, logger, and query helpers |
	| `packages/cli` | Validation, generation, OpenAPI, scaffolding, and the servers |
	| `packages/create-routa-ts` | The project scaffolder |
	| `apps/docs` | This documentation site |
	| `examples/*` | Runnable demonstrations of the public surface |

4. Verify against a real project. The examples run the `routa` binary, so build and link
   the local CLI before checking them.

	```sh
	pnpm prepare:local-cli
	pnpm --filter full-api check
	pnpm --filter full-api dev
	```

5. Add a changeset for any change to a published package.

	```sh
	pnpm changeset
	```

6. Update the documentation in the same pull request. Read `apps/docs/AGENTS.md` first; it
   defines the required page frame, the package-manager command component, and the
   structure each section uses.

</Steps>

## Verify

`pnpm verify` runs the complete gate: lint, typecheck, tests, generated-file drift, example
checks, OpenAPI checks, the scaffold error smoke test, and a packaging check. A change is
ready when it passes and the docs site builds.

```sh
pnpm verify
pnpm --filter @routa-ts/docs build
```

## Documentation Expectations

Every new feature needs all four of these, which is what the coverage rules in
`apps/docs/AGENTS.md` enforce:

- A reference entry with its signature, options, and one example.
- A mention in at least one guide showing it in a real workflow.
- An entry in Diagnostics for any new `ROUTA_*` code.
- A line in the implemented table on [v0 Scope & Status](/docs/start/v0-scope/).

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Workspace packages resolve to published versions | Run `pnpm install` from the root, not from inside a package. |
| An example fails after a core change | Rebuild first. Examples consume built output, so run `pnpm build`. |
| A formatter reports differences | Run `pnpm format` to apply them. |
| The docs build fails on a slug | A sidebar entry in `astro.config.mjs` points at a page that does not exist. |

<Aside type="note" title="Keep the contract aligned">
	Shipped behavior must agree across implementation, tests, and public documentation.
	Planned V1 work should come from an approved local Dex specification and ticket.
</Aside>
