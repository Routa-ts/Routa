Export `requireAuth` from a folder `middleware.ts` to protect every route below it: `export const signedIn = requireAuth({ schemes: ["session"] })`, or a re-export of a `const` another module binds to a literal call. The guard runs at its export position, before route and method middleware, and handlers below it get `ctx.auth` narrowed to the schemes they accept. Folder, route, and method guards compose by intersection: an operation accepts only the schemes every guard on its chain allows, Routa authenticates only credentials of those schemes, and a descendant cannot remove or widen an inherited requirement. Generated metadata, `ctx` types, OpenAPI security alternatives, and the automatic `401` outcomes follow the inherited requirement. `routa check` also reads a folder guard bound to a `const` alias or called on a namespace import of `@routa-ts/core` (`core.requireAuth()`), which inline guards and the `bearer`, `apiKey`, and `sessionCookie` descriptors in `src/routa.ts` accept too. It reports a folder guard it cannot read, such as a factory call at any depth, a conditional, or a destructuring, with `ROUTA_AUTH_REQUIREMENT_UNRESOLVED`, names each guard's file in `ROUTA_AUTH_REQUIREMENT_EMPTY`, and warns with `ROUTA_AUTH_REQUIREMENT_WIDENED` when a guard lists a scheme an earlier guard excludes. In an application that configures authentication, each `routaRoutes` entry now lists `middlewareFiles`, every folder `middleware.ts` on the route's path, and startup (`routa dev`, `routa start`, and `createTestApp`) refuses a folder `requireAuth` guard export the metadata does not list, such as one package code builds, so a guard Routa would not run never leaves routes public. Routa recognizes and enforces a guard built with another copy of `@routa-ts/core`, such as a package's own dependency, like one from the application's copy. Metadata without `middlewareFiles` in such an application fails at startup and asks you to run `routa generate`. Applications without authentication keep their generated metadata and start as before. An application middleware named `requireAuth` stays ordinary middleware; the migration guide in Middleware covers moving to the built-in guard.
