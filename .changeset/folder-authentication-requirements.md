Export `requireAuth` from a folder `middleware.ts` to protect every route below it: `export const signedIn = requireAuth({ schemes: ["session"] })`, or a re-export of a `const` another module binds to a literal call. The guard runs at its export position, before route and method middleware, and handlers below it get `ctx.auth` narrowed to the schemes they accept. Folder, route, and method guards compose by intersection: an operation accepts only the schemes every guard on its chain allows, Routa authenticates only credentials of those schemes, and a descendant cannot remove or widen an inherited requirement. Generated metadata, `ctx` types, OpenAPI security alternatives, and the automatic `401` outcomes follow the inherited requirement. `routa check` reports a folder guard it cannot read, such as a factory call or a conditional, with `ROUTA_AUTH_REQUIREMENT_UNRESOLVED`, names each guard's file in `ROUTA_AUTH_REQUIREMENT_EMPTY`, and warns with `ROUTA_AUTH_REQUIREMENT_WIDENED` when a guard lists a scheme an earlier guard excludes. `ROUTA_AUTH_REQUIREMENT_UNSUPPORTED` is removed. An application middleware named `requireAuth` stays ordinary middleware; the migration guide in Middleware covers moving to the built-in guard.
