Add optional Bearer authentication. Configure `authentication` in `createRouta` with one principal schema and a `bearer()` scheme, and every route gets typed `ctx.auth`: anonymous without a credential, authenticated after your authenticator accepts one. A presented credential that is malformed, unsupported, or rejected returns `authenticationFailed` (`401`) with a `WWW-Authenticate` challenge. An inline `requireAuth()` guard returns `authenticationRequired` (`401`) for anonymous requests and narrows `ctx.auth` for the handler. `routa check` reads the scheme facts from source and reports `ROUTA_AUTH_*` diagnostics, and generated OpenAPI declares the security schemes, each operation's security, and both outcomes. Applications without `authentication` generate the same metadata and OpenAPI as before, and their own authentication middleware, even one named `requireAuth`, keeps working with or without it. Configuring `authentication` reserves `ctx.auth`, so middleware that provides `auth` fails with `ROUTA_CONTEXT_RESERVED`; a route outcome or middleware reject with status `401` must differ from the authentication outcomes by a required literal property, or `routa check` reports `ROUTA_RESPONSE_STATUS_AMBIGUOUS`; and the outcome names `authenticationRequired` and `authenticationFailed` are taken (`ROUTA_OUTCOME_NAME_COLLISION`). `routa openapi breaking` no longer reports an operation as requiring authentication when its security includes the empty requirement `{}`.
