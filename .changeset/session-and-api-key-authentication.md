Add API-key and session-cookie authentication. `apiKey({ header, authenticate })` reads an API key from one request header, and `sessionCookie({ cookie, authenticate })` reads a session from one request cookie. Both use the same authenticator, principal schema, `ctx.auth`, failure, and challenge contract as `bearer()`. When a request presents several credentials, Routa selects the first by `authentication.priority`, which defaults to declaration order, and runs only that authenticator. It never falls back after a rejection. `multipleCredentials: "reject"` answers `ambiguousCredentials` (`400`) instead, before any authenticator runs. An inline `requireAuth({ schemes })` now also restricts which presented credentials Routa considers, so a valid credential of another scheme never authenticates the operation. Challenges default to `ApiKey` and `Session`, with an optional static `realm`. `routa check` reports overlapping transports, invalid header and cookie names, unknown, duplicate, or missing `priority` entries (`ROUTA_AUTH_PRIORITY_INVALID`), and guards on one operation that allow no scheme in common. Generated OpenAPI declares each scheme as a separate security alternative in priority order. `.routa/routes.gen.ts` exports `routaMultipleCredentials`, and startup refuses a `multipleCredentials` mode in `src/routa.ts` that differs from it. `CredentialChallenge` types the challenge override all three descriptors share.
