Static checks and formatting 11 features
Feature Adoption Use in Routa
Combined format, lint, and type check Use first Make vp check the framework static-check entry point after coverage is proven. Keep pnpm verify as the aggregate. Check
Syntax linting and reviewed fixes Use first Replace framework Biome lint commands with vp lint; map explicit rules, suppressions, and test exceptions before choosing a preset. Lint
Type-aware lint rules Use first Enable useful semantic rules, including unhandled and misused promises, for asynchronous request execution, cleanup, and CLI work. Enabling type analysis alone does not mean every rule is enabled. Oxlint type-aware guide
Compiler diagnostics during lint Pilot Enable typeAware and experimental typeCheck together, then compare source, test, and expected-failure coverage before removing tsc --noEmit. Type checking, stability
Formatting and format verification Use first Use vp fmt and vp fmt --check, retaining tabs, double quotes, semicolons, and the intended line width. Format
Import and package.json sorting Pilot Evaluate Oxfmt's import sorting and package.json sorting to replace Biome organization. Preserve side-effect import order and intentional scaffold text. Import sorting, package.json sorting
Tailwind class sorting Optional Apply Oxfmt's stylesheet-aware sorting to docs/design classes if it improves maintenance. Import and Tailwind sorting are disabled by default; package.json sorting is enabled by default. Sorting options
Markdown, MDX, CSS, YAML, JSON, and Astro formatting Optional Broaden checks deliberately, rather than reformatting every documentation file as an incidental migration. Astro formatting needs its optional compiler package and setting. Language support
Shared rules and file-specific overrides Use first Put lint/format policy in root vite.config.ts; express package and fixture differences through root overrides. Monorepos
JavaScript lint plugins and custom rules Optional Preserve an important rule unavailable natively using a compatible plugin. Write a custom rule only for a concrete recurring error. Plugin support
Cross-file import analysis Optional Evaluate import-cycle checks across framework modules. This is a linting aid, not Routa's route-graph analysis. Multi-file analysis

Feature Adoption Use in Routa

Test UI and performance diagnosis Optional Use the optional aligned @vitest/ui package in explicit watch mode, or Vitest's diagnostic tools when a suite hangs or slows down. UI, CLI

Workspace tasks, caching, and package builds 14 features
Feature Adoption Use in Routa
Workspace scripts and package filters Pilot Replace Turbo invocation with vp run --filter './packages/*' build while keeping package build scripts initially. Run
Explicit dependency graph Pilot Reproduce current build-before-typecheck and build-before-test ordering. Include relevant devDependencies; the CLI depends on the creator for development. Task dependencies
Parallel execution and concurrency Pilot Run independent checks concurrently after prerequisites. Avoid parallel mode for dependent builds. Concurrency
Local task-result caching Pilot Reuse deterministic builds and restore dist/**. Prove second-run hits, edited-input misses, and deleted-output restoration. Caching
Automatic file tracking Pilot Track reads, missing-file probes, directory listings, and writes without enumerating all source inputs. Validate with Routa's compiler API and subprocesses. Tracking
Explicit inputs, outputs, and environment Pilot Use cache.input, output, env, and untrackedEnv where inference is incomplete. Generic filesystem tracking cannot infer arbitrary environment reads. Cache configuration
Cache inspection and cleanup Optional Inspect hits/misses and clear task results during investigation. Cached success is evidence of replay, not evidence that validation reran. Cache commands
Cross-run GitHub Actions cache Optional Persist node_modules/.vite/task-cache after local correctness is proven. Upstream labels this workflow experimental; measure restore/save costs. Actions cache
Multiple package entry points Pilot Use vp pack to emit the current core exports and CLI/creator entries. Configure the separately spawned CLI runtime explicitly. Pack, entry points
Bundled/unbundled ESM and dependency control Pilot Preserve core module layout, bundled CLI internals, and deliberate runtime externals. Unbundled output, dependencies
Declaration generation Pilot Use a TypeScript-backed generator for inference-heavy public contracts. Verify emitted types against installed consumers. Declarations
Watch package builds Optional Use vp pack --watch for framework edits. Keep dependent output consumption and local CLI linking explicit. Pack watch
Build size reports Optional Inspect CLI/creator output size and unexpected dependency bundling; use raw sizes for Node packages and avoid paying for compressed-size reports when irrelevant. tsdown report options
publint and Are the Types Wrong Optional Add package metadata and declaration-resolution checks through tsdown. These optional integrations require publint and/or @arethetypeswrong/core and supplement real packed consumer tests. Package validation
