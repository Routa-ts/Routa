# Explicit authentication ownership and cookie effects

Routa V1 will preserve automatic fail-closed credential orchestration by default while allowing an operation to declare that its application handler owns credential processing, so acquisition and recovery endpoints can handle stale credentials without a provider-specific bypass. Handler-owned operations receive no framework authentication context or proof and cannot override inherited authentication requirements; custom credential extraction uses readonly declared HTTP sources without consuming the request body. This keeps authentication implementation with applications while making framework participation explicit in types, checks and metadata; runtime delivery remains pending.

Selected authenticator results may contribute source-authorized cookie effects through the shared response plan, including native cookie snapshots, independently of the later outcome's effects. Valid completed effects survive later ordinary failures, while invalid, unselected or late results contribute nothing and cookie conflicts follow safe-output handling without silently choosing a producer. Response selection, cancellation and actual resource completion remain separate contracts.
