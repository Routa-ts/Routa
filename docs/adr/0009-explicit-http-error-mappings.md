# Explicit error mappings preserve application ownership

Routa V1 will translate recognized application exceptions through explicit source-declared error mappings into ordinary typed named outcomes. Applications own error classes, meaning and public payloads; services import no Routa transport types. Folder policies inherit, while route-file and method declarations remain local. TypeScript checks mapping contracts but cannot infer or prove the set of errors a service might throw.

Framework failures retain explicit origin, status and protected effects independently of their public JSON presentation. Constructor matching covers escaping application middleware/handler exceptions rather than arbitrary failures in a broad catch. Construction, authentication providers, canonical cancellation, lifecycle cleanup and committed responses retain their existing owners. Unknown or failed mappings use a bounded safe server-error path without recursive matching.

Ordinary named outcomes retain proven-exclusive same-status/media composition. Framework failure alternatives, including the mandatory builtin fallback, may overlap a custom public schema. Their known OpenAPI schemas use truthful anyOf when necessary, including mixed framework/application composition, while the ordinary group still passes its original exclusivity checks and compatible effects remain required. This explicitly changes projection restrictions only for alternatives involving framework failures; it avoids hiding a possible wire response, rejecting ordinary custom formatter shapes or falsely emitting oneOf.

Framework body formatters are synchronous so an already selected failure does not depend on an additional asynchronous recovery stage. Application mappings may be asynchronous and remain part of the original request's signal, execution budget and actual resource lifetime. Error log severity is configurable and separate from expected/unexpected classification, HTTP status, telemetry and process exit. Log structure customization uses safe metadata and existing sanitized application-owned sinks rather than another backend or an unsafe automatic-event path.

The framework accepts explicit HTTP translation in exchange for inherited response possibilities and one narrow schema-projection exception. It does not own application error architecture, infer domain policy, require Result values or introduce a runtime registration system. Runtime implementation remains pending.
